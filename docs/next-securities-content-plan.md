## 1. 프로젝트 정의

- 브랜드: NEXT 증권 / NEXT Securities
- 서비스 정의: 미디어, AI 인텔리전스, 투자 경험을 준법 중심의 기술 구조로 연결하는 차세대 금융 투자 플랫폼
- 주요 대상: 금융기관, 전략적 파트너, 투자자, RFP 평가자 및 엔터프라이즈 의사결정자

- 핵심 약속: 복잡한 시장 데이터를 이해 가능한 인사이트로 전환하고, 준법 체계 안에서 콘텐츠 탐색과 투자 경험을 연결한다.

### 서브 메시지

### 브랜드 태도

- 유행보다 데이터에 집중한다.

- 초보자와 전문가를 구분하지 않고 각자에게 맞는 깊이를 제공한다.
- 기술은 앞에 드러내기보다 더 나은 투자 경험을 만드는 데 사용한다.

### B2B 핵심 메시지

> 전통 금융 시스템에 기술을 덧붙이는 방식이 아니라, Compliance-by-Design 기술 위에서 금융 경험을 새롭게 설계합니다.

클라우드 네이티브 및 Headless 아키텍처, 콘텐츠와 투자 경험을 연결하는 Media-First Trading Pipeline, 준법 체계 안에서 작동하는 AI-Native Intelligence Engine을 통해 차세대 테크 증권사의 새로운 기준을 제시합니다.

### 문구 사용 시 주의

- `기술 부채 제로` 대신 `구조적 기술 부채를 최소화하도록 설계된 아키텍처`를 기본 표현으로 사용한다.
- `완벽한 준수` 대신 `관련 규정과 내부 준법 기준을 반영한 설계`를 사용한다.
- `검증된 인사이트`는 검증 주체와 절차가 확인된 경우에만 사용한다.
- 경쟁사 또는 글로벌 서비스 수준을 직접 단정하지 않고 벤치마크 방향으로만 언급한다.

## 9. 결정적 차별점

### 9.1 Media-First Trading Pipeline

#### 개념

콘텐츠 탐색과 투자 실행 사이의 마찰을 줄이는 미디어 융합형 경험 파이프라인.

#### 전달할 경쟁력

- 단순 시황 나열을 넘어 AI가 가공한 숏폼 인사이트와 요약 콘텐츠를 제공한다.
- 콘텐츠 탐색, 종목 확인, 주문 화면 및 포트폴리오 탐색이 단절되지 않는 사용자 흐름을 설계한다.
- 특정 개인의 콘텐츠 역량이 아니라 CMS, 데이터, 승인 및 배포 프로세스로 시스템 자산화한다.

#### 안전한 표현

- `즉시 매수로 연결` 대신 `관련 투자 정보와 거래 화면을 자연스럽게 연결`
- `투자 기회를 추천` 대신 `시장 정보 탐색의 마찰을 최소화`
- `수익 가능한 종목` 대신 `관심 자산과 관련된 객관적 데이터`

### 9.2 AI-Native Intelligence Engine

#### 개념

Compliance-by-Design을 기반으로 시장 데이터를 가공하고 개인별 정보 탐색을 지원하는 지능형 데이터 레이어.

#### 전달할 경쟁력

- 공시, 뉴스, 리서치 및 시장 데이터를 전사 AI 백엔드에서 구조화한다.
- 사용자 관심 정보와 탐색 패턴에 따라 콘텐츠의 우선순위와 깊이를 조정한다.
- 준법 가이드라인과 승인 체계를 AI 콘텐츠 생성 및 노출 과정에 포함한다.
- 자문 또는 수익 예측으로 오인될 표현을 데이터 가공 단계부터 차단한다.

#### 안전한 표현

- `초개인화 투자 조언` 대신 `개인화된 정보 탐색`
- `검증된 매매 시그널` 대신 `객관적 시장 데이터와 리스크 신호`
- `AI가 판단` 대신 `AI가 정보의 탐색과 이해를 지원`

### 9.3 Global Tech Talent & RegTech Agility

#### 개념

글로벌 R&D 거점과 제도권 금융 수준의 RegTech 전문성을 결합한 기술 운영 체계.

#### 전달할 경쟁력

- 싱가포르 및 미국 법인을 글로벌 AI·IT 인재 확보와 기술 검증을 위한 R&D 거점으로 정의한다.
- 해외 핀테크 규제 및 샌드박스 사례를 국내 규정과 내부 통제 체계에 맞게 검토한다.
- 개인의 경력보다 조직의 개발 프로세스, 보안 체계, 준법 검토 및 운영 역량을 중심으로 설명한다.

> 해외 법인, 인재 구성 및 규제 프로그램 참여 여부는 공개 전 증빙 확인이 필요하다.

## 12. 4대 데이터 시각화 UX 패턴

### Pattern 1. 3D Capital Topology Heightmap

#### 목적

자본 유동성과 시장 데이터 밀집도를 3D 등고선 및 파티클 지형으로 표현한다.

#### 인터랙션

- 포인터 이동과 드래그에 따라 카메라 Pitch/Yaw가 제한 범위 안에서 반응한다.
- 스크롤을 통해 지형의 밀도와 높이가 단계적으로 변화한다.
- 선택된 구역은 NEXT Green으로 표시하고 데이터 출처와 기준 시점을 HUD에 함께 노출한다.
- 키보드 방향키와 Tab 탐색을 위한 대체 인터랙션을 제공한다.

#### 안전장치

- 실제 자본 건전성 수치는 검증된 최신 공시 데이터가 연결된 경우에만 표시한다.
- 데모 데이터 사용 시 `이해를 돕기 위한 샘플 시뮬레이션`임을 상시 명시한다.

### Pattern 2. AI Neural Network Constellation

#### 목적

뉴스, 리서치, 공시 및 시장 데이터가 AI 데이터 레이어에서 연결되는 과정을 노드와 연결선으로 시각화한다.

#### 인터랙션

- 노드 Hover 또는 Focus 시 NEXT Green으로 강조한다.
- 연관 데이터의 유형, 출처, 갱신 시점 및 요약 카드를 HUD로 제공한다.
- 노드 사이의 연결선은 데이터 연관성을 의미하며 매수·매도 추천을 의미하지 않는다.
- Tab, Enter 및 방향키로 동일한 정보를 탐색할 수 있도록 한다.

### Pattern 3. Cross-Border Asset Trajectories

#### 목적

통화 및 해외 자산 사이의 정산·이동 구조를 3D 궤적으로 표현한다.

#### 인터랙션

- 국가 및 자산 유형별 궤적을 필터링한다.
- 이동 단계, 처리 상태 및 기준 시간을 HUD에 표시한다.
- 실제 지원되지 않는 즉시 정산 또는 자산 이동 기능을 암시하지 않는다.

### Pattern 4. 3D Volatility Spectrum

#### 목적

전통적인 캔들 차트를 3D 캔들 파티클과 밀도 스펙트럼으로 재해석한다.

#### 인터랙션

- 기본 상태에서는 잔잔한 웨이브 모션으로 시장 변동성을 표현한다.
- Hover 또는 Focus 시 특정 구간의 데이터가 또렷하게 분리된다.
- 상승만 강조하는 색상 및 방향성을 피하고 상승·하락·중립 상태를 균형 있게 표현한다.
- High-DPI 환경에서 HUD 텍스트는 DOM 레이어로 분리해 선명도를 유지한다.

## 13. Compliance Overlay

### 기본 원칙

3D 시각화는 투자 권유, 특정 종목 추천, 수익률 예측 또는 개인별 자문으로 오인되지 않아야 한다.

### 카피 전환 기준

| 사용하지 않을 표현 | 안전한 대체 표현 |
|---|---|
| 실시간 특정 종목 매수 시그널 | AI가 가공한 시장 데이터 시뮬레이션 |
| 당신만을 위한 수익률 예상 지형 | 3D 자본 유동성 밀도 시각화 예시 |
| AI 추천 포트폴리오 | 관심 자산과 관련된 데이터 요약 |
| 위험 없는 투자 경로 | 시장 위험 요인에 대한 정보 |

### 상시 표시 정보

- 데이터 출처
- 기준 및 갱신 시점
- 실제 데이터 또는 샘플 데이터 여부
- 투자 판단 책임 및 원금 손실 가능성에 관한 고지
- 필요한 경우 준법감시인 심의필 번호와 유효기간

> 준법감시인 심의필 번호는 실제 승인 후 발급된 값만 사용한다. `제2026-OOOO호`와 같은 값은 기획 단계의 자리표시자이며 운영 화면에 노출하지 않는다.

## 14. Headless CMS 운영 아키텍처

### 목표

마케팅 및 운영 담당자가 WebGL 코드나 3D 파라미터를 직접 수정하지 않고 콘텐츠, 데이터 및 노출 상태를 관리할 수 있도록 한다.

### Structured 3D Block Schema

CMS 입력 항목 예시:

- 노드 대표 키워드
- 데이터 유형
- 데이터 출처
- 기준 및 갱신 시점
- 표시 수치
- 요약 설명
- 연결 URL
- 신호 색상
- 실제/샘플 데이터 구분
- 준법 승인 상태
- 게시 시작 및 종료 시간

### Preview & Scheduling

1. 작성자가 구조화된 데이터를 입력한다.
2. 미리보기 환경에서 3D 장면과 HUD를 검토한다.
3. 데이터 담당자가 출처와 수치를 확인한다.
4. 준법 담당자가 카피와 표현을 승인한다.
5. 승인 완료된 버전만 예약 발행한다.
6. 게시 이력과 승인 이력을 감사 로그로 남긴다.

### 콘텐츠 규모

- 110~140개 콘텐츠 운영을 기본 시나리오로 설계한다.
- 250~320개 이상으로 확장 가능한 블록 및 분류 체계를 사용한다.
- 실제 RFP 범위와 본수 산정 기준은 별도 확인한다.

## 15. Core Web Vitals 및 WebGL 성능 기준

### 로딩 전략

- Three.js 및 3D 장면은 Next.js `dynamic()`으로 지연 로드한다.
- HTML, 핵심 카피 및 CTA를 Canvas보다 먼저 렌더링한다.
- GLB, 텍스처 및 Draco 디코더는 필요한 구간 진입 전에 단계적으로 프리로드한다.
- 모바일 또는 저전력 환경에서는 단순화된 모델과 낮은 파티클 수를 사용한다.

### 렌더링 전략

- Intersection Observer로 활성 섹션만 렌더링한다.
- 뷰포트 밖 Canvas는 `requestAnimationFrame`을 중단한다.
- Vertex Buffer와 Geometry를 공유하고 가능한 오브젝트는 Instancing한다.
- `devicePixelRatio`에 상한을 두고 GPU 등급에 따라 렌더 해상도를 조정한다.
- 포인터 및 스크롤 입력은 시간 기반 감속 보간으로 처리한다.
- `prefers-reduced-motion`에서는 카메라 이동과 파티클 모션을 축소한다.

### 측정 지표

- LCP, INP, CLS
- 초기 JavaScript 전송량
- 3D 구간 평균 FPS
- GPU 프레임 시간
- GLB 및 텍스처 다운로드 크기
- 저전력 기기의 발열 및 배터리 영향

> `LCP 0.5초 이내`와 같은 목표는 네트워크, 기기 및 콘텐츠 조건을 정의한 성능 예산으로 관리하며 외부 공개용 보장 수치로 사용하지 않는다.
